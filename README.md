This repo will store solutions to programming problems for the Advent Of code (https://adventofcode.com/)

The primary programming language of all solutions should be SQL, some other pattern matching languages like grep/awk may be used to format input so that it can be loaded into a sql database, but a sql query should produce the final solutions to any non-trivial problem.

Repository layout:
```text
Makefile                    # Root shortcuts; defaults to YEAR=2025
2025/
  Makefile                  # PostgreSQL and per-day targets
  docker-compose.yml
  day-NN/
    readme.md               # Problem statement
    init.sql                # Creates the day's schema and loads the selected input
    part1.sql
    part2.sql
    example.dat             # Example input
    data-set.dat            # Your puzzle input; ignored by Git
```

# SQL Language Features

* **`CROSS JOIN`** combines every row from its left input with every row from
  its right input (a Cartesian product). Use it when every pairing is
  meaningful, such as combining each current selection state with the
  candidates generated for it.
* **`LATERAL` join** lets a subquery in the `FROM` clause refer to columns from
  an earlier `FROM` item. PostgreSQL evaluates that subquery for each preceding
  row, which is useful when the rows to generate or inspect depend on the
  current input row. In [Day 3, Part 1](2025/day-03/part1.sql), for example,
  the lateral subquery searches positions based on the bank and selection state.
* **Recursive CTE** (`WITH RECURSIVE`) defines a query in terms of its own
  results. It starts with an initial (anchor) query, repeatedly applies a
  recursive query to the rows found so far, and stops when an iteration
  produces no more rows. Use it for step-by-step processes such as traversing
  hierarchies or building a result incrementally; make sure each step moves
  toward a clear stopping condition.
* **`generate_series`** is a PostgreSQL set-returning function that creates one
  row per value in a sequence, such as a range of integers. Use it to turn
  positions or numeric ranges into rows that can be filtered, joined, and
  ordered. Day 3 uses it to enumerate eligible character positions in a bank.

# Developer Experience

## docker-compose

Use docker and docker compose to manage the postgres service that will serve as a base for all solutions.

## makefile

A Makefile for each year will be used with make targets to run each days solution

## 2025 quick start

Requirements: Docker with the Compose v2 plugin and GNU Make. No local PostgreSQL
installation is needed.

From the repository root (or from `2025/`):

```sh
make up
make psql
make run DAY=01 PART=1
make part2 DAY=01
make day-01 PART=1
make down
```

Run these commands from the repository root or `2025/`. The root Makefile
defaults to `YEAR=2025` and forwards targets to that year's Makefile. Run
`make help` for available targets. Use a two-digit `DAY` from `01` to `25`;
`PART` is `1` or `2`.

Each implemented day contains:

```text
2025/day-NN/
  data-set.dat
  example.dat
  init.sql
  part1.sql
  part2.sql
  readme.md
```

`init.sql` creates tables and loads the selected input; make it safe to rerun
(for example, drop and recreate that day's schema). `make init DAY=01` runs
setup alone. The `run`, `part1`, `part2`, and `day-NN` targets rerun setup
before executing the selected solution. `DATA` chooses the input filename
without its `.dat` extension and defaults to `data-set`; for example,
`make run DAY=01 PART=1 DATA=example` uses `day-01/example.dat`. Missing input
or SQL files and SQL errors fail the command; puzzle solutions and input files
are not generated by these targets.

The year directory is mounted read-only at `/aoc`. Each day's `init.sql` uses
the `DATA` selection to load `/aoc/day-NN/<DATA>.dat` with `COPY`. Use
day-specific schemas to keep solutions separate. PostgreSQL uses the
local-development database `aoc2025` with username/password `aoc`/`aoc`; no
database port is published to the host. `make psql DAY=01` initializes the
default input and opens a SQL shell with that day's schema in the search path.

Database data persists in a Docker volume across `make down` / `make up`.
To deliberately delete the 2025 database, run
`docker compose -f 2025/docker-compose.yml down --volumes` from the root.

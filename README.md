This repo will store solutions to programming problems for the Advent Of code (https://adventofcode.com/)

The primary programming language of all solutions should be SQL, some other pattern matching languages like grep/awk may be used to format input so that it can be loaded into a sql database, but a sql query should produce the final solutions to any non-trivial problem.

Repo layout:
year/
   docker-compose.yml
   Makefile
   day/
      readme.md - problem specification
      init.sql  - initializes the database, load data sets 
      part1.dat - part 1 data set
      part2.dat - part 2 data set

# Developer Experience

## docker-compose

Use docker and docker compose to manage the postgres service that will serve as a base for all solutions.

## makefile

A Makefile for each year will be used with make targets to run each days solution

## 2025 quick start

Requirements: Docker with the Compose v2 plugin and GNU Make. No local PostgreSQL
installation is needed.

From the repository root (or from `2025/`):

```sh
make up
make psql
make run DAY=01 PART=1
make part2 DAY=01
make day-01 PART=1
make down
```

The root Makefile defaults to `YEAR=2025`. Run `make help` for all targets.
Use a two-digit `DAY` from `01` to `25`; `PART` is `1` or `2`.

Each day should contain:

```text
2025/day-01/
  readme.md
  init.sql
  part1.dat
  part2.dat
  part1.sql
  part2.sql
```

`init.sql` creates tables and loads inputs; make it safe to rerun (for example,
drop and recreate that day's schema). `make init DAY=01` runs setup alone.
The run and part targets rerun setup before executing the selected solution.
Missing SQL files and SQL errors fail the command; puzzle solutions and input
files are not generated by these targets.

The year directory is mounted read-only at `/aoc`, so SQL can load input with
`COPY ... FROM '/aoc/day-01/part1.dat'`. Use day-specific schemas to keep
solutions separate. PostgreSQL uses the local-development database `aoc2025`
with username/password `aoc`/`aoc`; no database port is published to the host.
Use `make psql` to connect inside the container.

Database data persists in a Docker volume across `make down` / `make up`.
To deliberately delete the 2025 database, run
`docker compose -f 2025/docker-compose.yml down --volumes` from the root.
